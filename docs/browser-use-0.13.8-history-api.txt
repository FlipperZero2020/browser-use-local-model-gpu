- model brain: thinking text

The equivalent used in tools/browse.py and tools/phase5_gate.py, `list(json.loads(a.model_dump_json(exclude_none=True)))[0]`, also works because RootModel.model_dump_json serialises the root. With max_actions_per_step=1 (PLAN_DEFAULTS) the list has exactly one element; get_model_output() silently truncates anything beyond that, so extra actions the model emitted are not in history.

- the element the action targeted (resolved from the pre-action DOM)
    els = history.history[i].state.interacted_element or [None]*len(history.history[i].model_output.action);  el = els[k]  (list[DOMInteractedElement | None]  (browser_use.dom.views.DOMInteractedElement dataclass: node_id:int, backend_node_id:int, frame_id:str|None, node_type:NodeType, node_value:str, node_name:str (tag), attributes:dict[str,str]|None, bounds:DOMRect|None (x,y,width,height floats), x_path:str, element_hash:int, stable_hash:int|None, ax_name:str|None); el.to_dict() gives a plain dict)

When model_output is None the list is exactly [None]; on the synthetic max-steps tail item it is [].
- URL before the action
    history.history[i].state.url  (str  (BrowserStateHistory.url))
    state is the BrowserStateSummary captured in _prepare_context BEFORE the LLM call, i.e. what the model saw. '' on the synthetic max-steps tail item. history.urls() returns the same list.
- URL after the action
    history.history[i+1].state.url   (if i+1 < len(history.history) and history.history[i+1].metadata is not None)  (str)
    There is no post-action URL in item i; the next item's pre-action state is the only record. Not available for the last real step, and the synthetic tail item's url is '' (do not read it as 'navigated to blank'). ActionResult.long_term_memory for navigate/search says e.g. 'Navigated to <url>'.
- tabs / the tab
    history.history[i].state.tabs  -> list[TabInfo];  tab.url, tab.title, tab.target_id (full CDP TargetID), tab.parent_target_id;  page title: history.history[i].state.title  (list[browser_use.browser.views.TabInfo])
    The focused tab is not stored separately: find it as `next(t for t in h.state.tabs if t.url == h.state.url)`. `tab_id` (last 4 chars of target_id) exists only in serialized form (tab.model_dump()['tab_id'] / h.state.to_dict()['tabs'][k]['tab_id']) and is the form the model uses in the `switch` action's tab_id param. Compare target_id[-4:] to match.
- per-action results and errors
    history.history[i].result  -> list[ActionResult];  r = h.result[k];  r.error, r.extracted_content, r.long_term_memory, r.is_done, r.success, r.metadata, r.attachments  (list[browser_use.agent.views.ActionResult]: error: str|None; extracted_content: str|None; long_term_memory: str|None; is_done: bool|None (default False); success: bool|None; metadata: dict|None (click: {'click_x','click_y',...}; input: input coords); attachments: list[str]|None; judgement: None (use_judge=False))
    len(result) can be < len(action): multi_act breaks after an error, after done, after a terminates_sequence action, or when URL/focus changed. Effect text lives in long_term_memory/extracted_content, e.g. scroll -> 'Scrolled down the page 742px' / 'Scrolled up … 1.0 pages', click -> 'Clicked <desc>', input -> 'Input …', navigate -> 'Navigated to <url>'. history.errors() returns one entry per step (the FIRST r.error or None). A step where the LLM call itself failed has exactly one result: [ActionResult(error=<text>)] and model_output None.
- was this step an empty-action / invalid-JSON failure?
    h.model_output is None and h.result and h.result[0].error   # then classify by the error text prefix  (str error text; three distinct signatures (see caveats for the mechanics))
    (A) model emitted "action":[{}]  -> error startswith 'N validation errors for AgentOutput\naction.0.DoneActionModel.done\n  Field required [type=missing, input_value={}' (N=16 for browsin's registry). No 'Invalid model output format' prefix, because ChatOllama.ainvoke wraps pydantic's ValidationError in ModelProviderError(status_code=502) and AgentError.format_error only prefixes real ValidationError instances. One /api/chat record. (B) model emitted "action":[] (validates, min_items is schema-only) -> _get_model_output_with_retry re-asks once ('You forgot to return an action…' user message appended) -> TWO /api/chat records for the step; if the retry returned actions the step looks completely normal in history; if the retry was empty again, `self.ActionModel()` (the RootModel union) raises, giving error startswith 'Invalid model output format. Please follow the correct schema.\nDetails: 16 validation errors for ActionModelUnion\nDoneActionModel\n  Input should be a valid dictionary or instance of DoneActionModel [type=model_type, input_value=PydanticUndefined' — this is the signature quoted in PLAN.md §10; the 'safe noop done' fallback is broken in 0.13.8 for a multi-action registry. (C) malformed JSON (e.g. num_predict=1024 cut, proxy response.done_reason=='length') -> '1 validation error for AgentOutput\n  Invalid JSON: … [type=json_invalid'. (D) llm_timeout -> error == 'LLM call timed out after 600 seconds. Keep your thinking and output short.' (proxy record status 'CLIENT_ABORTED'). (E) step_timeout -> NO history item at all (see caveats). Also: a step whose action list was fine but the action failed has model_output set and result[k].error set — different thing.
- on-disk screenshot path (what the model was shown at this step)
    history.history[i].state.screenshot_path  (str | None  (absolute path);  base64: h.state.get_screenshot() -> str|None;  all: history.screenshot_paths() -> list[str|None])
    Written in Agent._make_history_item via ScreenshotService.store_screenshot(browser_state_summary.screenshot, self.state.n_steps) -> f'{agent_directory}/screenshots/step_{n_steps}.png'. Saved even when model_output is None (LLM failure) as long as the browser state had a screenshot. None on the synthetic tail item and on any initial_actions item (step_number 0; browsin has none).
- step timing
    history.history[i].metadata.step_start_time, .step_end_time, .step_number, .step_interval, .duration_seconds  (StepMetadata | None: step_start_time: float (epoch, time.time()), step_end_time: float (epoch), step_number: int (1-based n_steps), step_interval: float|None, duration_seconds: property = end - start)
    metadata is None on the synthetic max-steps tail item. step_interval is misnamed: it is the PREVIOUS item's duration (prev_end - prev_start), not a gap. step_start_time is set at the top of Agent.step() (before DOM capture); step_end_time at the top of _finalize (after actions) — so duration = DOM build + LLM call(s) incl. any empty-action retry + action execution. Wall-clock epoch, unlike proxy.jsonl's monotonic offsets (see proxy section). Also useful: h.state_message: str|None — the full text of the browser_state user message the model saw (element list with indices), from MessageManager.last_state_message_text.

import json

def actions_of(h):
    """Yield (name, params_model, emitted_dict, effective_dict, element, result) for step item h (AgentHistory)."""
    if h.model_output is None:            # LLM call failed this step -> nothing to extract; see h.result[0].error
        return
    acts = h.model_output.action          # list[ActionModel]; ActionModel is a pydantic RootModel[Union[...]] in 0.13.8
    els = h.state.interacted_element or [None] * len(acts)
    for k, a in enumerate(acts):
        emitted = a.model_dump(exclude_unset=True)      # delegates to a.root -> {'scroll': {'down': False, 'pages': 2.5}} (only keys the model sent)
        name = next(iter(emitted))                      # exactly one key: the action name
        effective = a.model_dump()[name]                # defaults filled in -> {'down': True, 'pages': 1.0, 'index': None} for {"scroll": {}}
        params = getattr(a.root, name)                  # typed model. NOTE: getattr(a, name) raises AttributeError -- must go through .root
        el = els[k] if k < len(els) else None           # DOMInteractedElement | None (None also when the index did not exist in the DOM shown)
        res = h.result[k] if k < len(h.result) else None  # ActionResult | None (result list may be shorter than action list)
        yield name, params, emitted, effective, el, res

=== SCREENSHOT ===
Path for step i: `history.history[i].state.screenshot_path` (str | None). It is produced in Agent._make_history_item (browser_use/agent/service.py:1748-1764) as str(ScreenshotService.screenshots_dir / f'step_{self.state.n_steps}.png'), where screenshots_dir = agent_directory / 'screenshots' and agent_directory = Path(tempfile.gettempdir()) / f'browser_use_agent_{agent.id}_{int(time.time())}' computed once in Agent.__init__ (service.py:446-448). So the file is `<tempfile.gettempdir() at Agent() time>/browser_use_agent_<uuid7>_<epoch>/screenshots/step_<metadata.step_number>.png`. The number is the 1-based n_steps at store time (== h.metadata.step_number), NOT the list index; a step cancelled by step_timeout has no file and no item, so numbers can skip. Base64 of the same bytes: `h.state.get_screenshot()` (None if path missing/unreadable). All paths: `history.screenshot_paths()` (list with None placeholders) or `history.screenshot_paths(return_none_if_not_screenshot=False)`.

Where files land under browsin: tools/browse.py (lines 32-39) and tools/phase5_gate.py (44-54) set `os.environ['TMPDIR'] = str(SCRATCH)` AND `tempfile.tempdir = str(SCRATCH)` before importing browser_use, with SCRATCH = REPO/runs/browse-<YYYYmmdd-HHMMSS>/tmp (phase5: its own runs/phase5-<ts>/tmp). Because tempfile.gettempdir() caches its answer on first call, that is exactly where agent_directory goes. Confirmed on disk for a real run: runs/browse-test-20260905-023649/tmp/browser_use_agent_06a9bc69-3b89-7a54-8000-3ffa40ca7fdf_1788593811/screenshots/step_1.png … step_8.png (also browseruse_agent_data/todo.md next to it; siblings browser-use-user-data-dir-*, browser-use-downloads-*, downloads/). The screenshot is the state shown to the model at that step (captured before the action), and it is the very same bytes that went to ollama: llm_screenshot_size is None in browsin (no _resize_screenshot), so sha256(open(screenshot_path,'rb').read()) == proxy record request.images[0].sha256 — verified 8/8 on that run. Per-step prompt text lives beside it in runs/<run>/conversation/conversation_<agent.id>_<n>.txt (save_conversation_path), written only for steps whose LLM output parsed, so a missing <n> marks a failed step.

=== PROXY JSONL ===
One JSON object per line, appended by browsin/proxy.py _Handler._relay (in its `finally`, i.e. when the exchange COMPLETES, so line order is completion order — sort by `seq` before correlating). Top-level keys: `seq` (int, 1-based arrival order across ALL paths), `t_start` / `t_end` (float seconds of time.monotonic() relative to Proxy.__enter__'s t_origin — NOT wall clock), `elapsed_s` (t_end - t_start), `method` ('POST'), `path` ('/api/chat' for every LLM call; /api/ps,/api/tags,/api/show would pass through too but do not occur in browse runs), `status` (int HTTP status, or the string 'CLIENT_ABORTED' = caller disconnected before the reply was written, which is what an llm_timeout looks like, or 'UPSTREAM_ERROR' with an extra `error` string), `response_bytes` (int), `request` (dict), `response` (dict; ABSENT on CLIENT_ABORTED/UPSTREAM_ERROR or unparseable body). `request` = {'body_bytes': int, 'model': 'qwen2.5vl-32k:7b', 'stream': False, 'options': {'num_ctx': 32768, 'num_predict': 1024 in newer runs}, 'num_ctx': int (copy of options.num_ctx), 'format_present': bool, 'format_bytes': int (size of the JSON schema, ~12101), 'tools_present': bool, 'tools_len': int|None (0: ollama's client sends tools: []), 'keep_alive': value or '<absent>', 'message_count': int, 'messages': [{'role': 'system'|'user'|'assistant', 'chars': int}, ...], 'total_text_chars': int, 'image_count': int, 'images': [{'bytes': int, 'sha256': hex, 'png': [w, h] | None}] (or {'decode_error': True})}; for a bodiless GET request is {'body_bytes': 0}; a non-JSON body gives {'body_bytes', 'parse_error': True}. `response` = subset of Ollama's /api/chat reply: {'model', 'done': True, 'done_reason': 'stop' | 'length' (num_predict hit -> truncated JSON -> step parse failure), 'prompt_eval_count': int (prompt tokens actually evaluated — the only place the prompt size is observable; ChatOllama discards it and history.usage is None/zeros), 'eval_count': int (generated tokens), 'prompt_eval_duration', 'eval_duration', 'total_duration', 'load_duration' (ints, nanoseconds)}. Reader helpers: Proxy.records(), Proxy.chat_records() (path startswith '/api/chat'), Proxy.first_vision_request() (lowest-seq chat record with image_count > 0); offline just json.loads each non-blank line of runs/<run>/proxy.jsonl.

Correlating records to steps (there are normally exactly 1 chat record per history item that has model_output or an LLM-error result, but MORE when the empty-action retry fired, and records for steps that left no history item): PRIMARY — match by image hash: rec['request']['images'][-1]['sha256'] == hashlib.sha256(open(h.state.screenshot_path,'rb').read()).hexdigest(). Each request carries exactly the current step's screenshot (use_vision=True keeps only the current one, image_count==1, no resize), so this is exact; verified 8/8 on runs/browse-test-20260905-023649. Then: one step with TWO matching records = an "action": [] empty-action retry (second record has one more user message — but message_count also rises for nudges/last-step warnings, observed 2->3 at seq 6-8 of that run, so never use message_count alone); a matching record with status 'CLIENT_ABORTED' and no response = that step's llm_timeout (its line may be appended late — the handler waits up to UPSTREAM_TIMEOUT_S=1800 s for the box — so it can appear out of seq order, after later steps, or never if the proxy exited first); a record whose sha matches no file = a step that produced no history item (step_timeout cancellation) or a screenshot that was never stored; records with image_count 0 = compaction/judge/extract calls (all disabled/excluded in browsin — treat as a config regression). FALLBACK when the sha is unusable (screenshot None, or the 4x4 placeholder PNG for about:blank giving identical hashes): walk chat records in seq order and assign to history items in order, consuming 1 per item, +1 extra for an item whose error text contains 'ActionModelUnion' / 'PydanticUndefined' (retry exhausted) — an item with a normal model_output can still hide a retry, which is why the sha method is preferred; sanity-check rec['elapsed_s'] <= h.metadata.duration_seconds. Clock note: proxy t_start/t_end are monotonic offsets with no wall-clock anchor in the file; in-process convert with wall = time.time() - (time.monotonic() - proxy.t_origin) + rec['t_start'] and compare to h.metadata.step_start_time (epoch); offline you cannot.

=== CAVEATS ===
- ActionModel is a RootModel union in 0.13.8: `getattr(action, name)` raises AttributeError; use `getattr(action.root, name)`. `action.model_dump(...)` is overridden to return the inner {name: params} dict, and `model_dump_json` serialises the root, so the dict/JSON forms work either way.
- `model_dump(exclude_unset=True)` shows only what the model literally emitted and hides defaults (scroll down=True/pages=1.0, input clear=True, done success=True, search engine='duckduckgo'). For the EFFECTIVE value read the typed model or `model_dump()` with no exclude flags. {"scroll": {}} is a valid action meaning scroll down one page.
- model_output.thinking / evaluation_previous_goal / memory / next_goal are all `str | None`; model_output itself is None on every LLM-failure step. metadata is None on the synthetic max-steps tail item. state.interacted_element can be [None] or [] (tail item). Always guard.
- Two different 'empty action' shapes with different footprints: "action": [{}] fails pydantic validation inside ChatOllama and surfaces as a ModelProviderError step error ('16 validation errors for AgentOutput / action.0.DoneActionModel.done / Field required', 1 chat record, model_output None, counted in consecutive_failures); "action": [] passes validation and triggers _get_model_output_with_retry (2 chat records inside the same llm_timeout) — if the retry succeeds the history item is indistinguishable from a normal step, and if it fails again `self.ActionModel()` raises ('Invalid model output format… ActionModelUnion … input_value=PydanticUndefined') because the 'safe noop done' fallback cannot instantiate a RootModel union.
- ChatOllama wraps EVERY exception (pydantic ValidationError, httpx errors, invalid JSON) as ModelProviderError(status_code=502); Agent.get_model_output then tries the fallback LLM (none configured) and re-raises, so result[0].error is the bare str(e) without the 'Invalid model output format' prefix — do not key on that prefix except for the retry-exhausted case.
- History index != step number. A step cancelled by step_timeout (900 s in browsin) leaves NO AgentHistory item — _finalize returns early because last_result was cleared — but n_steps still advances, so step_number skips and screenshots/step_<n>.png is missing for it; the model sees the error in the next prompt but the diagnoser sees nothing unless it reads the proxy record. Use h.metadata.step_number, never i+1.
- Run termination paths differ: max_steps exhausted appends a synthetic item (model_output None, metadata None, state.url '' with tabs [], result [ActionResult(error='Failed to complete task in maximum steps')]); stop after max_failures+1 (=6) consecutive failures appends nothing; done breaks the loop right after the done step.
- history.final_result() returns result[-1].extracted_content of the LAST item regardless of whether it was `done` — check history.is_done() / result[-1].is_done first. history.is_successful() is the model's own `success` flag; PLAN §5 forbids grading on it.
- done text: full text is in DoneAction.text and result[-1].extracted_content (plus '\n\nAttachments:…' only if files_to_display matched files); result[-1].long_term_memory is TRUNCATED to 'Task completed: {success} - {text[:100]} - {N} more characters'. Do not read the answer from long_term_memory or from the next step's prompt.
- len(result) may be shorter than len(action) (multi_act stops at the first error/done/page change) and get_model_output truncates parsed.action to max_actions_per_step (=1 in browsin), so any additional actions the model emitted are lost before history. Zip with care.
- state.url/title/tabs/screenshot are PRE-action (captured in _prepare_context before the LLM call). Post-action URL only exists as the next item's state.url. The focused tab is not stored; match state.url to state.tabs[k].url. TabInfo.target_id is the full CDP id; the 4-char `tab_id` exists only in serialized output (model_dump / to_dict) and is what the `switch` action's tab_id param carries.
- interacted_element[k] is None both for index-less actions and for an index that did not exist in the DOM shown (an invented index) — distinguish using action.get_index() is not None.
- history.usage is useless on this path (ChatOllama returns usage=None, token service reports zeros); prompt_eval_count from proxy.jsonl is the only prompt-size measurement.
- proxy.jsonl lines are written on completion, not arrival: sort by seq. CLIENT_ABORTED (llm_timeout) records may land long after later steps or be lost if the proxy shuts down while the upstream is still generating (UPSTREAM_TIMEOUT_S = 1800 s). `response` is absent on CLIENT_ABORTED/UPSTREAM_ERROR.
- request.message_count / total_text_chars grow for reasons other than a retry (budget warning, last-step 'only done is available' message, replan nudges) — observed 2->3 at seq 6 of an 8-step run. Identify a retry by two consecutive records sharing the same image sha256, not by message_count.
- response.done_reason == 'length' means num_predict (1024) cut the generation; the step will then show a json_invalid ValidationError text in result[0].error. Also G5 in phase4_gate treats any non-'stop' as an offender.
- browsin never persists AgentHistoryList (no save_to_file call anywhere in browsin/ or tools/); a diagnoser must run in-process or call history.save_to_file(path) itself; reloading needs AgentHistoryList.load_from_file(path, AO) with AO rebuilt from the same registry (Tools(exclude_actions=DEFAULT_EXCLUDED_ACTIONS) + AgentOutput.type_with_custom_actions). AgentHistory.model_dump is custom (state via to_dict, tabs with 4-char tab_id).
- Any offline script that imports browser_use must import browsin.env first (zero-cloud env block, before DEFAULT_BROWSER_PROFILE is evaluated) and should set TMPDIR/tempfile.tempdir first — the import itself leaks a browser-use-user-data-dir-* temp dir; constructing Tools()/create_action_model()/AgentOutput types is offline and network-free (this is what was run here), but never construct Agent, BrowserSession or ChatOllama in the diagnoser.
- metadata.step_interval is misnamed (previous step's duration). step_start_time/step_end_time are epoch seconds (time.time()); proxy t_start/t_end are monotonic offsets from Proxy.__enter__ — different clocks, no anchor in the file.
- h.state_message (str | None) holds the exact browser_state text the model saw at that step (element list with indices) — the right place to check whether a clicked index existed, cheaper than re-deriving from interacted_element.
- save_conversation_path writes conversation_<agent.id>_<n>.txt only when the LLM output parsed (state.last_model_output set); a gap in <n> is another marker of a failed step. Nothing in the registry names match 0.9.7 docs: actions are `click`, `input`, `scroll`, `navigate`, `search`, `switch`, `done` (not click_element/input_text/go_to_url/switch_tab).
